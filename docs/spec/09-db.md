# db Bench

The db Bench connects to databases, shows their schema and runs SQL. Connections are shared by the Bench's Lab.

## Engines

R-DB-001. Engines in v1:

| Engine | Driver | Default port |
|---|---|---|
| PostgreSQL | `github.com/jackc/pgx/v5` | 5432 |
| MySQL and MariaDB | `github.com/go-sql-driver/mysql` | 3306 |
| SQLite | `modernc.org/sqlite` | none, a file path |

R-DB-002. Redis, MongoDB and ClickHouse `[later]`.

## Connection

R-DB-003. A Connection has: id, name, engine, host, port, database, user, TLS mode, Tunnel (the name of an ssh Bench Host, or `user@host[:port]`, and an optional key file), read-only flag, color, order index, and the Lab that shares it.

R-DB-004. For SQLite, host, port, user and TLS are empty; `database` is the file path. A relative path is relative to the Bench's effective root folder.

R-DB-005. TLS modes: off, prefer, require, verify-ca, verify-full. The default is prefer. MySQL maps verify-ca and verify-full to `tls=true` with a custom config; PostgreSQL maps them to `sslmode`.

R-DB-006. The password lives in the Keychain under the service `dev.sviniabanditka.notch-lab` with the account `db/<connection id>/password` (R-SHELL-165). Connections without a password are allowed.

R-DB-007. Connections are stored in `$NOTCH_LAB_HOME/db/connections.json` as an array, without secrets. The file is written after every change.

R-DB-008. The read-only flag is on by default. On a read-only Connection the app refuses a write statement before it runs (see R-DB-040).

R-DB-009. A Connection with a Tunnel opens an SSH connection to the host, checking its key against `~/.ssh/known_hosts`, with `golang.org/x/crypto/ssh` before the database connection. Keys come from the Host's identity file, else from every `~/.ssh/id_*` file, else from the ssh-agent at `$SSH_AUTH_SOCK`. The database connection dials through the SSH connection to `host:port`. A Tunnel that fails shows the SSH error in the Panel row.

R-DB-010. The Connection sheet (new, edit) has fields for every attribute of R-DB-003, a password field, and a "Test" button. Test connects, runs `SELECT 1`, and shows "OK, 42 ms" or the error. Save without Test is allowed.

R-DB-011. Deleting a Connection asks for confirmation, closes its Queries' connections, and removes its Keychain item.

## Connecting

R-DB-020. The app opens the database when the user clicks the Connection or runs a Query on it. The app keeps one pool per Connection, of at most 4 connections (1 for SQLite); each statement takes one connection for its run.

R-DB-021. A connection attempt times out after 10 s and shows the error in the Panel row.

R-DB-022. A connection that drops reconnects with backoff: 1 s, 2 s, 4 s, 8 s, then every 15 s, up to 5 minutes. The Panel row shows "Reconnecting". A Query sent during that time waits for the reconnect, up to its timeout.

R-DB-023. Disconnect from the context menu closes every connection of that Connection. Open Query Tabs stay open and reconnect on the next Run.

## Panel

R-DB-030. The Panel shows Connections in order, each with a colored dot, its name, and its state: idle, connecting, connected, reconnecting, error.

R-DB-031. A connected Connection expands to its schema tree:

| Level | PostgreSQL | MySQL | SQLite |
|---|---|---|---|
| schema | each schema except `pg_*` and `information_schema` | each database on the server | one node `main` |
| group | Tables, Views, Functions | Tables, Views, Routines | Tables, Views |
| object | one table, view or function | same | same |
| column | name, type, NULL or NOT NULL, PK, FK marker | same | same |
| index | under a table, after columns: name, columns, unique | same | same |

R-DB-032. The tree reads the catalog with one query per level when the user expands a node. A level that takes over 300 ms shows a spinner in the node.

R-DB-033. The Panel header has a search field. The tree shows only objects whose name contains the query, with their parents. A search runs over the loaded levels; the app loads all tables of every schema at the first search.

R-DB-034. "Refresh" in a Connection's context menu, or Cmd+R with the Panel focused, reloads the tree and keeps expanded nodes expanded.

R-DB-035. A table's context menu:

| Item | Effect |
|---|---|
| Select 500 rows | opens a Query Tab with `SELECT * FROM <table> LIMIT 500` and runs it |
| Count | runs `SELECT count(*) FROM <table>` and shows the count in a Toast |
| Show DDL | opens a read-only Query Tab with the DDL |
| Copy name | copies the qualified, quoted name |

R-DB-036. DDL per engine: PostgreSQL builds it from the catalog (columns, constraints, indexes); MySQL runs `SHOW CREATE TABLE`; SQLite reads `sqlite_master.sql`.

R-DB-037. Double-click on a table runs "Select 500 rows". Double-click on a column copies its name.

## Query Tab

R-DB-040. A Tab holds one Query against one Connection. Type data: `{"connection": "<id>", "file": "<path or empty>", "sql": "<text when no file>"}`. The title is the file name, else the first 40 characters of the SQL, else "Query".

R-DB-041. Cmd+T opens a new empty Query on the selected Connection, else on the Connection of the focused Tab, else asks for a Connection.

R-DB-042. The Tab layout from top to bottom: a toolbar, the SQL editor, a Divider, the Results. The Divider's position is stored in the Bench settings as `resultsRatio`, default 0.5.

R-DB-043. The toolbar has: the Connection select with its color, Run, Run all, Cancel (while a run is active), a read-only badge when the Connection is read-only, a "Limit 500" toggle, the timeout field in seconds (default 30).

R-DB-044. The SQL editor is the native editor with SQL highlight. The Explorer and Preview of the editor Bench do not apply.

R-DB-045. Cmd+Enter runs the selection when there is one, else the statement under the cursor. A statement ends at `;` outside a string or comment. Cmd+Shift+Enter runs every statement in order.

R-DB-046. The app adds `LIMIT 500` to a SELECT that has no LIMIT and no FETCH when the "Limit 500" toggle is on. The default is on. The Results show a bar "500 rows shown" with "Load more", which runs the statement again with `LIMIT 500 OFFSET <n>` and appends.

R-DB-047. The app runs a statement in auto-commit. A manual transaction mode `[later]`.

R-DB-048. A statement runs with a context that times out after the Tab's timeout. A timeout cancels the statement on the server (`pg_cancel_backend` through pgx's cancel, `KILL QUERY` for MySQL, `sqlite3_interrupt`) and shows "Timed out after 30 s".

R-DB-049. Cancel does the same for a running statement.

R-DB-050. Before a run the app classifies each statement by its first keyword after comments:

| Class | Keywords |
|---|---|
| read | SELECT, WITH, SHOW, EXPLAIN, DESCRIBE, PRAGMA (without `=`), VALUES, TABLE |
| write | INSERT, UPDATE, DELETE, MERGE, REPLACE, UPSERT, PRAGMA with `=` |
| ddl | CREATE, ALTER, DROP, TRUNCATE, RENAME, GRANT, REVOKE, VACUUM, ANALYZE, REINDEX |
| control | BEGIN, START, COMMIT, ROLLBACK, SET, USE, CALL, DO, other |

R-DB-051. On a read-only Connection a write, ddl or control statement does not run. The messages area shows "Read-only connection. Turn read-only off in the Connection settings to run this."

R-DB-052. On a Connection with read-only off, a confirmation sheet shows before: an UPDATE or DELETE without WHERE; any DROP, TRUNCATE or ALTER. The sheet shows the statement and the Connection name, with "Run" and "Cancel". A `WITH ... UPDATE` counts as an UPDATE.

R-DB-053. The classifier is a text scan. A statement it cannot classify is "control" and needs read-only off.

R-DB-054. EXPLAIN with a plan view `[later]`.

R-DB-055. Cmd+S saves the SQL to the Tab's file. A Query without a file asks for a name and writes `<name>.sql` in the Bench folder. The Bench folder follows R-HTTP-001 and R-HTTP-002 with `db` in place of `http`. The Panel lists saved Queries under "Saved" below the Connections.

## Results

R-DB-060. Each statement that returns rows produces one Result tab. Run all produces one Result tab per statement, named "1", "2", ...; the last one is selected.

R-DB-061. A statement without rows shows its message: "12 rows affected, 8 ms".

R-DB-062. The Result grid draws only visible rows. 500 rows of 50 columns scroll at 60 fps.

R-DB-063. Column headers show the name and the type. A click sorts the loaded rows by that column; a second click reverses; a third click clears. Sorting is client-side over loaded rows only.

R-DB-064. A filter row under the headers takes text per column. The grid shows rows whose cell text contains the filter. Filtering is client-side.

R-DB-065. NULL shows as `NULL` in the secondary color and italic. An empty string shows as empty. Binary shows as `<n bytes>`. JSON and JSONB show as one line.

R-DB-066. A cell over 200 characters shows truncated with an ellipsis. Enter or double-click on a cell opens a cell view: the full text, pretty JSON when it parses, with "Copy".

R-DB-067. Copy: Cmd+C copies the selected cells as TSV; the context menu has "Copy row as JSON", "Copy column", "Copy as INSERT".

R-DB-068. Export (toolbar button over the grid): CSV, JSON (array of objects), SQL INSERTs. Export writes the loaded rows. A dialog offers "Export all rows" which re-runs the statement without LIMIT and streams to the file; a run over 1 000 000 rows asks for confirmation.

R-DB-069. Cell editing with a generated UPDATE `[later]`.

R-DB-070. The messages area under the Results shows notices (PostgreSQL NOTICE, MySQL warnings) and errors. An error with a position (PostgreSQL `Position`, SQLite offset) moves the editor's cursor to that position and underlines the token.

R-DB-071. A Result that completes while the Tab is off screen marks the Tab Unread.

## History

R-DB-080. The app appends every run statement to `$NOTCH_LAB_HOME/db/history/<connection id>.jsonl`: timestamp, the SQL, duration, row count or error. The file keeps the last 200 lines.

R-DB-081. The toolbar "History" button shows the list. A click inserts the SQL at the cursor.

## MCP tools, domain `db`

R-DB-090. Tools:

| Tool | Input | Output | Level |
|---|---|---|---|
| `db.connections.list` | `{bench?}` | Connections: id, name, engine, host, database, read-only, state | Read |
| `db.schema.get` | `{connection, schema?, table?}` | the tree at that level, as R-DB-031 | Read |
| `db.query.run` | `{connection, sql, limit?, timeout?}` | columns with types, rows up to `limit` (default 500, max 5000), duration, row count, truncated flag | Read for read statements; Full for write, ddl and control |
| `db.query.explain` | `{connection, sql}` | `[later]` | Read |
| `db.result.last` | `{tab}` | the last Result of that Tab, up to 500 rows | Read |

R-DB-091. `db.query.run` follows R-DB-050 to R-DB-053: a read-only Connection refuses writes for every Client. A Client at Full with read-only off runs writes without the confirmation sheet; the app shows a Toast "<client> ran UPDATE on <connection>" and writes the Audit log.

R-DB-092. `db.query.run` runs in a Tab owned by the Client on the focused db Bench, or in a hidden connection when the Bench's Lab is not shown. The Tab is created when absent.

R-DB-093. No tool returns a password. `db.connections.list` returns no connection string.
